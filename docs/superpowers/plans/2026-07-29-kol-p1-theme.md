# Kol P1 — Theme Crate & Design System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `kol-theme` as the single source of truth for Kol's design tokens, with a generator that emits the design-system HTML card library from those same declarations, so the TUI and the design system cannot drift.

**Architecture:** Tokens are Rust constants declared once via a macro that produces both the `Color` const the TUI uses and a `Swatch` registry entry the card generator reads. A `gen_cards` binary renders the registry into standalone HTML files under `design-system/`, each carrying a first-line `@dsCard` marker. A test regenerates in memory and compares against the committed files, so drift fails `cargo test`.

**Tech Stack:** Rust 1.92.0 (pinned by `rust-toolchain.toml`), `ratatui` 0.29 (for `Color` only), std only otherwise. No new third-party dependencies.

**Spec:** `docs/superpowers/specs/2026-07-29-kol-design.md` — this plan implements §4 (Design system) and §5.1 (`kol-theme`).

## Global Constraints

- **Toolchain is pinned.** Rust 1.92.0 via `rust-toolchain.toml`. Do not add a `rust-version` key or bump anything.
- **Always scope cargo commands with `-p kol-theme`.** The workspace has ~76 members; a full-workspace build is slow enough to derail the task.
- **`canonicalize` is banned** by clippy `disallowed-methods`: `std::fs::canonicalize`, `Path::canonicalize`, `tokio::fs::canonicalize`. Use `dunce::canonicalize` if a path must be canonicalized. This plan never needs it.

- **New code lives in `kol-theme`.** Per spec §2.1, this tree is a one-way sync from an upstream monorepo; logic in new crates never conflicts. P1 touches no `xai-grok-*` source file.
- **Crate naming:** the crate is `kol-theme` (hyphen), the Rust path is `kol_theme` (underscore).

use ratatui::style::Color;

/// Parse a `#rrggbb` literal into a [`Color`] at compile time.
///
/// Panics during const evaluation on a malformed literal, so a typo in any token declaration
/// fails the build instead of silently rendering the wrong colour.
pub const fn hex(s: &str) -> Color {
    let b = s.as_bytes();
    assert!(b.len() == 7, "hex literal must be exactly 7 bytes: #rrggbb");
    assert!(b[0] == b'#', "hex literal must start with '#'");
    Color::Rgb(
        nibble(b[1]) * 16 + nibble(b[2]),
        nibble(b[3]) * 16 + nibble(b[4]),
        nibble(b[5]) * 16 + nibble(b[6]),
    )
}

const fn nibble(c: u8) -> u8 {
    match c {
        b'0'..=b'9' => c - b'0',
        b'a'..=b'f' => c - b'a' + 10,
        b'A'..=b'F' => c - b'A' + 10,
        _ => panic!("hex literal contains a non-hex digit"),
    }
}

/// Composite `fg` over an opaque `bg` at `alpha` (0–255), matching CSS `rgba()` over a solid
/// backdrop.
///
/// A terminal cell has no alpha channel, so the design's translucent diff-row fills must be
/// pre-composited against the surface they sit on. Integer math throughout, so this is usable
/// in const context and its result is exactly reproducible.
pub const fn composite(fg: Color, bg: Color, alpha: u8) -> Color {
    let (fr, fg_g, fb) = match fg {
        Color::Rgb(r, g, b) => (r, g, b),
        _ => panic!("composite requires Color::Rgb"),
    };
    let (br, bg_g, bb) = match bg {
        Color::Rgb(r, g, b) => (r, g, b),
        _ => panic!("composite requires Color::Rgb"),
    };
    Color::Rgb(mix(fr, br, alpha), mix(fg_g, bg_g, alpha), mix(fb, bb, alpha))
}

const fn mix(f: u8, b: u8, a: u8) -> u8 {
    (((f as u16) * (a as u16) + (b as u16) * (255 - a as u16)) / 255) as u8
}
```

    /// Const name, e.g. `ACCENT`.
    pub name: &'static str,
    /// The `#rrggbb` literal as written in the design.
    pub hex: &'static str,
    /// The parsed value the TUI uses.

/// Declare a colour group once, producing the consts and the registry together.

/// Emulate CSS `letter-spacing` by interleaving spaces between characters.
///
/// The design applies `.1em`–`.28em` tracking to every label and display string (`KOL`,
/// `STANDING BY`, `RECORDING`, `CONSENT REQUIRED`). A terminal cannot space glyphs
/// sub-character, so the equivalent is a literal space between them. Words are separated by
/// two spaces so they remain distinguishable from intra-word spacing.
///
/// Leading and trailing whitespace is dropped and internal runs collapse to a single word
/// break, which matches how these strings are used — they are short fixed labels, never
/// user-supplied prose.
///
/// ```
/// use kol_theme::tracking::tracked;
/// assert_eq!(tracked("STANDING BY"), "S T A N D I N G  B Y");
/// ```
pub fn tracked(s: &str) -> String {
    s.split_whitespace()
        .map(|word| {
            let mut out = String::with_capacity(word.chars().count() * 2);
            for (i, c) in word.chars().enumerate() {
                if i > 0 {
                    out.push(' ');
                }
                out.push(c);
            }
            out
        })
        .collect::<Vec<_>>()
        .join("  ")
}
```

```rust
use crate::color;
use ratatui::style::{Modifier, Style};

/// The five emphasis roles the design's 11-step font-size scale collapses to.
///
/// A terminal has no font sizes. Hierarchy is carried by colour, weight, and tracking instead.
/// Each variant records the design measurement it stands in for, so the card generator can
/// show the original alongside the terminal equivalent.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Role {
    /// The one oversized string on a screen. `STANDING BY`.
    Display,
    /// Screen titles and Kol's own speech.
    Title,
    /// Default running text.
    Body,
    /// Uppercase section labels. `TRANSCRIPT`, `BLAST RADIUS`.
    Label,
    /// Timings, counts, keyboard hints.
    Meta,
}

/// Every role, in hierarchy order.
pub const ROLES: &[Role] = &[
    Role::Display,
    Role::Title,
    Role::Body,
    Role::Label,
    Role::Meta,
];

impl Role {
    /// The ratatui style for this role.
    pub fn style(self) -> Style {
        match self {
            Role::Display => Style::default()
                .fg(color::semantic::ACCENT)
                .add_modifier(Modifier::BOLD),
            Role::Title => Style::default()
                .fg(color::text::PRIMARY)
                .add_modifier(Modifier::BOLD),
            Role::Body => Style::default().fg(color::text::BODY),
            Role::Label => Style::default().fg(color::text::DIM),
            Role::Meta => Style::default().fg(color::text::FAINT),
        }
    }

    /// Whether strings in this role should be passed through
    /// [`crate::tracking::tracked`] before rendering.
    pub const fn is_tracked(self) -> bool {
        matches!(self, Role::Display | Role::Label)
    }

    /// The design measurement this role stands in for.
    pub const fn design_source(self) -> &'static str {
        match self {
            Role::Display => "22px / letter-spacing .28em",
            Role::Title => "14–17px",
            Role::Body => "12.5px / line-height 1.7",
            Role::Label => "10–10.5px / letter-spacing .18–.24em",
            Role::Meta => "10.5px",
        }
    }

    /// Lowercase name used in generated card markup.
    pub const fn name(self) -> &'static str {

/// Base codepoint of the Unicode braille block. Each cell packs a 2×4 sub-pixel grid, which is
/// what lets the field render at four times the terminal's vertical resolution.
pub const BRAILLE_BASE: u32 = 0x2800;

/// Sub-pixel columns per braille cell.
pub const CELL_COLS: u16 = 2;

/// Sub-pixel rows per braille cell.
pub const CELL_ROWS: u16 = 4;

/// Point-cloud density: the prototype's `density` prop default.
pub const DENSITY_DEFAULT: usize = 2300;
/// Lowest density the prototype permits.
pub const DENSITY_MIN: usize = 300;
/// Highest density the prototype permits.
pub const DENSITY_MAX: usize = 2600;

/// Render geometry of a field surface, measured in terminal cells.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct FieldGeometry {
    pub cols: u16,
    pub rows: u16,
}

impl FieldGeometry {
    /// The left rail field. 46×32 cells in the prototype.
    pub const RAIL: Self = Self { cols: 46, rows: 32 };

    /// The full-width graph field. 108×32 cells in the prototype.
    pub const GRAPH: Self = Self { cols: 108, rows: 32 };

    /// Sub-pixel resolution of this field, as `(width, height)`.
    pub const fn subpixels(self) -> (u16, u16) {
        (self.cols * CELL_COLS, self.rows * CELL_ROWS)
    }

    /// Total addressable sub-pixels. An upper bound on useful point density.
    pub const fn capacity(self) -> u32 {
        let (w, h) = self.subpixels();
        w as u32 * h as u32
    }
}

/// Cards are entirely self-contained — the Design System pane blocks requests to external

/// Lowercase a name and replace anything that is not alphanumeric with a hyphen.
pub fn slug(s: &str) -> String {
    s.chars()
        .map(|c| {
            if c.is_ascii_alphanumeric() {
                c.to_ascii_lowercase()
            } else {
                '-'
            }
        })
        .collect()
}

/// Render a [`ratatui::style::Color::Rgb`] back to a CSS hex string.
///
/// The card chrome styles itself from the same tokens the TUI uses, so the design system is
/// rendered in its own palette rather than a hand-written approximation of it.
pub fn hex_of(c: ratatui::style::Color) -> String {
    match c {
        ratatui::style::Color::Rgb(r, g, b) => format!("#{r:02x}{g:02x}{b:02x}"),
        other => panic!("hex_of expects Color::Rgb, got {other:?}"),
    }
}

```rust
//! Generate the Kol design-system card library from the tokens in `kol-theme`.
//!
//! Run from anywhere in the repo:
//!
//! ```text
//! cargo run -p kol-theme --bin gen_cards
//! ```
//!
//! Output is written to `design-system/` at the repo root and is committed. The
//! `no_drift` integration test fails if the committed files stop matching what the tokens
//! produce, which is what keeps the design system from drifting away from the binary.

use kol_theme::cards;
use std::path::PathBuf;

fn main() -> std::io::Result<()> {
    let out = output_dir();
    std::fs::create_dir_all(&out)?;

    let cards = cards::all();
    for card in &cards {
        let path = out.join(card.path());
        std::fs::write(&path, card.to_html())?;
        println!("wrote {}", path.display());
    }
    println!("{} cards generated", cards.len());
    Ok(())
}

/// Repo-root `design-system/`, resolved from this crate's manifest directory so the binary
/// works regardless of the shell's current directory.
fn output_dir() -> PathBuf {
    PathBuf::from(env!("CARGO_MANIFEST_DIR"))
        .join("../../..")
        .join(cards::OUTPUT_DIR)
}

- [ ] **Step 8: Write the drift guard**

Create `crates/codegen/kol-theme/tests/no_drift.rs`:

```rust
//! Fails if the committed card library no longer matches what the tokens produce.
//!
//! This is the mechanism behind the spec's claim that the design system cannot drift from the
//! binary: regenerating is the only way to change a card, and forgetting to regenerate is a
//! test failure rather than a silent inconsistency.

use kol_theme::cards;
use std::path::PathBuf;

fn output_dir() -> PathBuf {
    PathBuf::from(env!("CARGO_MANIFEST_DIR"))
        .join("../../..")
        .join(cards::OUTPUT_DIR)
}

#[test]
fn committed_cards_match_the_tokens() {
    let dir = output_dir();
    for card in cards::all() {
        let path = dir.join(card.path());
        let committed = std::fs::read_to_string(&path).unwrap_or_else(|e| {
            panic!(
                "{} is missing ({e}). Run: cargo run -p kol-theme --bin gen_cards",
                path.display()
            )
        });
        assert_eq!(
            committed,
            card.to_html(),
            "{} is stale. Run: cargo run -p kol-theme --bin gen_cards",
            path.display()
        );
    }
}

#[test]
fn no_orphaned_cards() {
    let dir = output_dir();
    let expected: Vec<String> = cards::all().iter().map(|c| c.path()).collect();
    let entries = std::fs::read_dir(&dir).expect("design-system/ exists");
    for entry in entries {
        let name = entry.expect("readable entry").file_name();
        let name = name.to_string_lossy().to_string();
        if !name.ends_with(".html") {
            continue;
        }
        assert!(
            expected.contains(&name),
            "{name} is in design-system/ but no card generates it — delete it or add the builder"
        );
    }
}
```
